# 寻迹实验室 · THU Pathfinding Lab

面向「智能交通创新实践」课程的四轮车视觉寻迹测试平台。Python / FastAPI 后端，React / TypeScript 工作台，普通 CPU 即可运行。

现已提供四种可直接运行的参考算法：**扫描线 PD、时序拓扑 + 调速 Pure Pursuit、时序拓扑 + MPC、端到端 CNN + GRU**。Pure Pursuit 和 MPC 共用视觉层，学习模型附带实际 CPU 训练权重。方法与训练复现见 [算法说明](docs/algorithms.md)，真实成功率与失败案例见 [算法验收结果](docs/algorithm-results.md)。手动驾驶和原有平台探针仍可使用。

## 安装与启动

需要 Python **3.10–3.13**。在项目目录打开终端：

```bash
python scripts/setup.py --mirror
python run.py
```

Linux 如果没有 `python` 命令，将上面两行的 `python` 换成 `python3`。`--mirror` 使用清华 PyPI 镜像和 npmmirror；使用官方源时省略它。

浏览器访问 **http://127.0.0.1:8000**。

安装脚本自动创建 `.venv`、安装锁定依赖、配置项目内的 Node.js 22 并构建前端；**无需手动激活虚拟环境，也不必单独安装 Node.js**。后续启动只需 `python run.py`，前端由同一服务提供，不需要再开 npm 服务。首次安装需要联网，之后正常仿真和界面运行不依赖外部网络。中文字体随前端打包。

已验证系统和真实检查结果见 [平台验收记录](docs/acceptance.md)。Windows 采用相同入口和跨平台路径，但尚未实际测试。Linux 若系统 Python 缺少 `venv` 模块，先安装发行版对应的 Python venv 组件。

常用命令：

```bash
python run.py doctor
python run.py serve --port 8001
python run.py test
python run.py scenes --seeds 7 8
python run.py benchmark --algorithms stop constant --seeds 101 102 --steps 400
```

不需要网页的环境可以只安装 Python：`python scripts/setup.py --skip-frontend --mirror`，然后运行批量评测。

## 运行实验

直接在「算法 / 操作方式」选择「时序拓扑 + 调速 Pure Pursuit」或「时序拓扑 + 预测控制 MPC」，选择场景后启动即可；无需额外配置。算法会显示候选线、选中路径、动作和状态。默认上限已增加到 4000 帧，以覆盖长距离「同线多段可见」场景。

自定义地图接近车辆最小转弯半径时优先选择 MPC。当前学习模型定位为教学基线，在平行干扰线上仍存在失败；所有失败与非法换线记录均保留。

端到端算法额外安装一次 CPU 运行库，然后重启服务即可选用附带权重：

```bash
python scripts/setup_learning.py
python run.py
```

学习依赖和权重不可用时，前端明确标注；其余算法和手动驾驶不受影响。当前学习权重针对默认绿色起点标记训练，其他初始化提示请使用模块化方案。

手动验收步骤：

1. 默认选择「闭环仿真 → 直线 → 手动驾驶」，点击「启动实验」。
2. 增大目标速度，再调整前轮转角；摄像头画面、俯视车体和实际轨迹应随之变化。
3. 按 `↑/↓` 调整速度，按住 `←/→` 转向，松开转向键回正；空格制动。键盘操作时不要将焦点放在输入框内。
4. 点击「暂停」后车辆应停止推进仿真时间；「单步」只推进一次。暂停允许正在计算的一帧完成。
5. 点击「停止」终止回合；「重置」创建新实例并停在首帧。切换场景或算法前先停止当前回合。
6. 运行结束后进入结果回放，拖动时间轴，导出 JSON / CSV。在「运行记录与对比」中选择多次实验比较。
7. 切换到「单帧图像」或「视频 / 图像序列」，上传素材，选择分割探针，检查候选线和 `frames_seen` 跨帧计数。

手动控制 0.6 秒未更新会请求制动；窗口失焦请求停车。网页 30 秒无心跳时，当前实验自动取消并记录原因。停止/故障后的制动也遵守减速度约束，制动帧单独保存。

录制视频的后续画面不会随动作改变；该模式只用于感知与时序分析。没有真值或标定的素材不生成米制误差和闭环成功率。

## 算法提交与自定义地图

学生在「算法提交」下载模板，在 `StudentAlgorithm` 中实现 SDK 生命周期，把 `algorithm.py` 与辅助代码、权重文件打包成 ZIP，填写名称和输出类型后点击「上传并选用」，再点击「启动实验」。不需要拿到或修改平台的 `algorithms.json`。ZIP 根目录或唯一的一层文件夹中放置入口文件；平台自动解压、静态校验、登记并持久保存。

运行目录为该次上传的代码目录，因此可以按相对路径读取资源、导入辅助模块。平台已提供 NumPy、OpenCV 和 SDK，额外第三方库由教师统一安装；不会执行 ZIP 中的安装脚本或自动安装 `requirements.txt`。每次上传作为一个新版本，运行记录保存该 ZIP 的 SHA-256。完整接口见 [SDK 与接入协议](docs/protocol.md)，前端不再保留「接入与使用」章节。

「自定义地图」支持点击添加、拖动或输入控制点，自动以直线与相切圆弧生成路线。圆角至少为 `轴距 / tan(最大转角) × 1.02`；控制点过密、近似原地折返、非相邻路段交叉或间距不足都会明确拒绝。可以调整车辆、相机、线宽、材质与种子，预览起点图像，保存 / 加载地图，导入 / 导出 JSON，再应用到实验。保存的场景会完整复制进运行记录，后续改图不会改变历史实验。

「同线多段可见」已扩展为五段相邻路线、交替回头弯和末端 S 弯。工作台的「场景模型」可切换立体 / 俯视视图，旋转观察角度；四轮、前轮内外转角、车架与相机支架按米制坐标显示。材质采用固定在地面的确定性程序纹理。

运行记录可逐条或批量删除，删除前有确认；运行中的记录须先停止。删除包括记录和该回合额外保存的图像，不删除共用素材或算法包。

## 结构

```text
pathlab/            SDK、配置、仿真、评测、进程执行与 HTTP 服务（按职责分文件）
frontend/src/       React 工作台、可视化面板与类型
algorithms/        扫描线基线、模块化视觉/控制、学习训练/推理与真实权重
student_template/  可直接复制的 Python 模板及独立进程入口
scenarios/         八类核心场景实例与压力场景
tests/             协议、仿真、评分、故障、HTTP 与 WebSocket 回归
scripts/           一次性安装、真实浏览器验收
docs/              架构、协议、评分和实际验收说明
artifacts/         运行、素材、算法包、自定义地图、报告与截图
run.py             统一启动、测试、场景生成与评测入口
algorithms.json    本地算法注册表
```

基础平台无需 ROS、Gazebo、数据库或 PyTorch；PyTorch 仅用于可选学习算法。插件与模拟器通过独立、版本化的 SDK 协议通信。

## 保存、评测与课程使用

- 每次实验保存在 `artifacts/runs/<run_id>/`，包含 `manifest.json` 和逐帧 `frames.jsonl`。
- 保存场景、种子、公开提示、算法版本/参数、环境、协议与评分器版本、原始有效输出、执行动作、干预和失败原因。
- 默认不复制每帧图片。仿真回放按保存的输入位姿和种子重建；录制素材保存在 `artifacts/uploads/`。
- JSON / CSV 导出用于分析；完整迁移回放请同时保留 `runs` 和对应 `uploads`。仿真重建要求保持相同渲染器和依赖版本；需要逐字节留存时启用图像记录。
- 大小、并发、超时和保留上限均明确限制，见 [架构与运行边界](docs/architecture.md)。不自动删除学生结果；可在运行记录页面显式删除。
- 批量评测先保存计划，再运行所有指定组合；失败场景也进入报告。

```bash
# 快速平台回归：八类场景，每类两个预先固定的种子
python run.py benchmark --algorithms stop constant --seeds 101 102 --steps 400

# 完整工作进程评测，包含协议传输与逐帧记录
python run.py benchmark --algorithms temporal_pursuit temporal_mpc --seeds 1001 1002 1003 1004 1005 --split test --steps 4000 --output artifacts/independent
```

参考算法结果见 [算法说明](docs/algorithms.md)；早期 [平台探针报告](artifacts/benchmark/report.md) 保留为链路验收记录。停车和固定动作失败不代表参考算法的能力。

教师评测规则、指标定义与防止进度跳跃的约束见 [评分与公平比较](docs/evaluation.md)。任务假设和阶段状态见 [实施进度](docs/progress.md)。

## 开发与限制

前端修改后重新运行 `python scripts/setup.py --mirror`，或在已激活虚拟环境的终端中执行 `cd frontend`、`npm run build`。开发热更新可以用 `npm run dev`，同时启动 `python run.py`。

维护者可额外安装 Playwright 并运行真实浏览器验收；具体命令见验收记录。它不属于学生启动平台的必需依赖。

这是平面地面、针孔相机、运动学自行车模型的教学仿真。立体视图用于观察，摄像头仍使用标定一致的地面投影；没有轮胎侧滑、动态曝光、实体碰撞、三维遮挡或硬件闭环。地图检查是几何可行性检查，不保证给定速度下跟踪成功；速度、加速度和转角变化率仍由仿真约束。当前上传执行用于教师本机的受控代码，独立进程提供超时与故障清理，**不是恶意代码安全沙箱**，尚无账号隔离或多人权限控制。默认仅监听 `127.0.0.1`。
