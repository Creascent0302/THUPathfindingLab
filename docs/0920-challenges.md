# 0920 挑战地图与独立避障方案

本页保留避障 **1.0** 的开发历史与成绩。当前 **2.0** 的 0920 用户地图修复、配对回归和剩余失败见 [避障 v2](avoidance-v2.md)。

本轮保留原有沿线算法，增加 `temporal_pursuit_avoidance` 与 `temporal_mpc_avoidance` 两个独立入口。主页、批量评测和运行记录都按不同算法识别；不通过一个算法内的避障开关混合成绩。

## 地图库

## 三轮开发

先对原算法做基线检查：最新的用户图两种时序拓扑算法均能通过；较早交通锥布局均在约 18% 进度处碰撞。额外构造的四个无障碍近邻线 / 相机变化案例，原两种方法均为 4/4，不能声称这些地图已使时序拓扑失效。真正暴露不足的是占道和遮挡。

1. 第一轮加入独立的图像障碍物估计、候选绕行和停车约束。后续路线被遮挡时，直接停车导致三个障碍图均失败；还发现深蓝灰道路会被颜色阈值误识别为物件。
2. 第二轮加入有限侧移观察与原路线记忆。「占道与邻线」两种控制器均成功，但套圈图仍有停车超时或接入返回段的问题；连续占道仍失败。
3. 第三轮保留这些反例，收紧遮挡续段关联，加入暂时离开视野的邻线记忆、平滑参考线、限定绕行幅度，并要求以新观测确认重新接回。MPC 用实际绕行请求速度做预测。中间版本也有回退：灰色物件的运动残差误报、旧视觉边界的路径折点和交通锥白色条纹分裂均单独分析，不把失败排除出统计。

各中间版本的计划、哈希、所有成功 / 失败指标及终止诊断保存在 [iterations](../artifacts/algorithms/0920-hard/iterations)。这些是已用于调试的开发集，不能称为未知测试。旧基线部分使用评分器 3.0；避障开发使用 4.0，不能直接比较两版总分。最终配对评测必须使用相同的完整地图、步数预算和 4.0 规则。

## 复现

```bash
python scripts/evaluate_algorithms.py \
  --algorithms temporal_pursuit temporal_mpc temporal_pursuit_avoidance temporal_mpc_avoidance \
  --scene-files artifacts/algorithms/0920-hard/scenes/block-coil.json \
                artifacts/algorithms/0920-hard/scenes/block-neighbor.json \
                artifacts/algorithms/0920-hard/scenes/block-double.json \
                artifacts/algorithms/0920-hard/scenes/user-0920.json \
                artifacts/algorithms/0920-hard/scenes/user-0920-obstacles.json \
  --steps 1500 --jobs 4 --output artifacts/challenge-search/reproduce-0920
```

算法只得到 RGB 和公开 SDK 信息。评分器独立检查有序路线、真实车体碰撞及绕行区域；算法自报的 `avoidance_active` 不会影响成绩。遇到看不清或无法通过的路径，请看结束原因、进度、碰撞和非法换线，而不是只看算法是否显示 TRACK。

两种避障方案目前定位为彩色物件、平面场地的教学基线。灰色、低对比物体、连续完全遮挡、狭窄且看不到后续的绕行空间仍可能失败。它们不依赖特权地图，也不具备从单目图像恢复所有障碍物的保证。原有不避障算法始终可单独选择。

## 冻结后的验证

最终开发集采用评分器 4.0、同一地图快照、每回合最多 1500 帧，共 20 回合；百分比为最终合法进度，包含全部失败。原 PP / MPC 各 1/5 成功，独立避障版本各 3/5 成功；避障版本无碰撞或非法换线，但两张困难图仍停车超时。

| 地图 | 原 PP | 原 MPC | PP + 避障 | MPC + 避障 |
|---|---|---|---|---|
| 0920挑战·套圈占道 | 碰撞 7.6% | 碰撞 7.6% | 成功 99.4% | 成功 99.4% |
| 0920挑战·占道与邻线 | 停车超时 10.4% | 停车超时 10.2% | 成功 99.4% | 成功 99.4% |
| 0920挑战·连续占道 | 碰撞 8.7% | 碰撞 8.7% | 停车超时 15.6% | 停车超时 15.1% |
| 用户最新 0920 | 成功 99.5% | 成功 99.4% | 成功 99.5% | 成功 99.4% |
| 用户旧 0920（紧邻障碍） | 碰撞 18.5% | 碰撞 17.7% | 停车超时 8.7% | 停车超时 8.4% |

连续占道的第二个物件，以及旧 0920 在弯曲近邻段的物件遮挡，仍会使局部规划无法确认后续路线。这些失败保留在地图库和分母中，不称为全部通过。完整指标、停止诊断与冻结代码摘要见 [final-results.json](../artifacts/algorithms/0920-hard/final-results.json)。

两个镜像障碍图使用保留种子 10021，冻结策略后首次运行：两种避障方法各 2/2 成功，共 4/4；无碰撞、无非法换线。它们验证左右绕行对称性与渲染种子变化，但共享开发图拓扑，不是四个独立拓扑样本。原始摘要见 [heldout-results.json](../artifacts/algorithms/0920-hard/heldout-results.json)。

另外以保留种子 10023 检查直线、回头弯、同线多段可见，两种避障方法各 3/3 成功，共 6/6。使用默认场景中的路侧物件，任务上限 2000 帧，见 [core-results.json](../artifacts/algorithms/0920-hard/core-results.json)。

真实 JSONL Worker 在「占道与邻线」上完整运行两个避障版本，均成功且没有碰撞或非法换线；包含惯性制动及最终结果保存。每次使用临时实验目录，最终 manifest 保存在 [protocol](../artifacts/algorithms/0920-hard/protocol)。快速脚本和 Worker 的耗时口径不同，本轮多个检查同时运行，实时性数值不作为跨方法速度结论。

全量测试 199 项、真实浏览器 9 组流程通过，前端构建通过。启用本次后台和评分器修改需要重启 `python run.py`，然后刷新浏览器；无需重新安装依赖。
