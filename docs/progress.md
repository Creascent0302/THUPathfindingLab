# 实施范围与验收进度

平台阶段已经完成；用户最新要求已授权进入正式算法阶段。本轮实现四种架构 / 控制方案，并执行实际训练、闭环验证与保留集测试。

实施顺序：
1. A：公共协议、配置、确定性运动学、透视相机、场景生成。
2. B：独立进程接入、任务与存储、三种模式、中文界面、回放和评分。
3. 平台验收：数值与防作弊测试、故障恢复、真实浏览器交互、批量样例。
4. C / D：模块化目标连续跟踪、两种控制器、扫描线基线、端到端训练与模型。

验收不能以停车、固定动作或简单分割示例的行驶成功率代表正式算法能力。
性能结论必须以真实闭环报告为依据；不提供空实现、随机权重或专家回退伪装的端到端结果。

## 固定任务假设

- 世界和车辆均采用米、弧度、秒；世界 Z 向上。车辆原点在后轴中心，X 前、Y 左。
- 正转角向左；速度非负，不倒车。自行车运动学使用等效前轮转角，静止时不改变朝向。
- 可识别的绿色起点圆环和方向箭头为默认公开输入；可改颜色/大小，或用首帧像素点/矩形提示。
- 算法仅接收 RGB、相机内参与车辆坐标到图像的地面单应矩阵、时间和显式提示。
- 不发送世界位姿、地图、种子、场景名称、私有目标身份或评分。
- 核心场景无分叉；回头弯半径受车辆转弯能力约束。压力场景单独标注。
- 默认固定步长 0.05 s；推理时间、仿真时间、浏览器刷新时间分别记录。
- 确定性模式不按推理墙钟时长推进物理时间；硬超时失败并安全制动，绝不替代算法。
- 压力模式按仿真帧注入固定延迟和种子化掉帧，动作过期时制动。
- 这是平面视觉/运动学教学仿真，地面加入程序纹理，未建模轮胎侧滑、悬架、动态曝光和三维遮挡。
- 本地可信插件使用进程隔离；该机制不是恶意代码安全沙箱。
