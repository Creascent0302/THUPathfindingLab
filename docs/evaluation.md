# 评分、批量评测与公平比较

评测器版本 `2.0`，综合评分版本 `2.0`。原有接入、连续进度、偏离、非法换线、终点容差保持不变；新版增加物件碰撞检测、结束后的惯性制动检测与可解释综合分。所有阈值、完整场景、车辆配置、算法身份和评分版本都随结果保存。

## 在页面批量测试

1. 打开「批量评测」，选择算法、统一执行模式、内置地图或已保存的自定义地图。
2. 输入互不重复的测试种子、单次最大帧数、推理超时。必要时在「各方法参数」填写以算法 ID 为键的 JSON，例如 `{"temporal_mpc":{"speed_mps":0.7}}`。
3. 点击「启动批量评测」。平台先冻结所有场景、物件和车辆配置，再串行启动独立 Worker，每个案例重新初始化算法。
4. 在「方法对比」查看完整配对结果，在「逐项结果」检查失败原因、展开分数分项、回放或导出单次结果。批次可以导出 JSON 和带 UTF-8 BOM 的 CSV。

单批最多 128 次运行，最多 3 个未结束批次，共用平台的 200 条运行记录、3 个活跃 Worker 与 2 GiB artifacts 配额。批次串行执行；已有交互实验占满 Worker 时排队等待，磁盘/记录配额不足时保留失败信息。取消会停止当前 Worker，并标记尚未运行的案例。删除批次汇总保留单次运行记录；删除单次记录后，批次保留当时的指标快照，但对应回放和原始帧导出将不可用。

批次使用后台模式，关闭浏览器或离开评测页不会取消。服务正常退出会取消未完成批次；崩溃后重启会保留已完成结果，将悬而未决的作业标记中断。不会静默重跑、补齐或把部分结果视为完整测试。

内置地图按每个种子重新生成。自定义地图保留保存的路线、物件、初始位置、车辆与相机设置，各种子仅改变场景内依赖种子的外观噪声。种子不等于独立的新地图拓扑。批次不会将已使用的开发种子自动改名为未知测试；训练、调参、验证和保留测试的真实使用历史需要维护。

## 核心成功规则

私有目标路线是有序折线。评分器维护累计弧长，局部投影允许向后搜索 0.35 m、向前搜索本步实际位移的 1.5 倍加 0.025 m；不在回头弯的整张地图中直接选择最近线段作为进度。

| 条件 | 规则 |
|---|---|
| 合法接入 | 起点后 0–0.5 m 弧长内，投影距离 ≤0.20 m、航向误差 ≤0.45 rad |
| 有效跟踪 | 距离 ≤0.24 m、航向误差 ≤0.65 rad 时增加有序进度 |
| 成功 | 连续进度进入终点前 0.18 m 容差、仍满足跟踪约束，且后续停车未碰撞 |
| 持续偏离 | 接入后连续 2 s 不满足跟踪约束 |
| 非法换线 | 干扰线距车辆 <0.14 m，且比目标线近至少 0.035 m，持续 0.5 s |
| 无效位移 | 一步位移超过最大车速 × dt × 1.05 + 0.001 m |
| 超时 | 达到预先声明的任务步数；任务期间停车也消耗步数 |
| 碰撞 | `render_version=3` 的启用且可碰撞物件与实际车体平面轮廓接触 |

碰撞使用后轴坐标系车体矩形：中心在轴距一半处、长宽取车辆配置；与障碍物的真实平面轮廓做分离轴检测。静态物件轮廓/AABB 缓存，远处物件先排除。对两帧间的平移和旋转按最大 4 cm 的扫掠步距细分，步距同时不超过车辆宽度和最小物件尺寸的一半，以检测越过细小物件的情况。这是固定步长近似扫掠检测，不是刚体碰撞反弹求解器。碰撞后平台仍按物理模型制动，保存接触事件和滑行轨迹。

首次到达终点记录 `success_at_s`。终止后的制动不再累加路线进度或产生新的换线判定，但继续检测碰撞；此时碰撞可将暂时的 success 改为 collision。禁用物件、`collidable=false` 物件以及旧渲染版本 1/2 的物件不参与碰撞。

算法报告 TRACK、FINISHED 或高置信度不会覆盖评分器真值。`policy_finished`、算法错误、手动取消、浏览器断线、记录配额耗尽均不等于成功。没有标注真值的图像/视频只提供感知与时序记录，不产生闭环成功、碰撞或综合分。

## 综合分：独立于成功条件

令有效完成度为 `c∈[0,1]`，质量分为 `q∈[0,1]`：

- 成功运行：`score = 60 + 40q`，范围 60–100。
- 失败运行：`score = 49c(0.5 + 0.5q)`，不超过 49。
- 没有进度的停车运行得 0；没有真值时为 `null`，不假定零误差或成功。

| 质量分项 | 权重 | 归一化公式 |
|---|---:|---|
| 跟踪精度 | 35% | `max(0, 1 − 跟踪误差P95 / 0.24 m)`；无有效跟踪样本取0 |
| 行驶效率 | 20% | `min(1, 有效弧长 / (车速上限 × 任务仿真时间))`；无前进时间取0 |
| 转向平滑 | 15% | `max(0, 1 − 实际转向速率绝对值P95 / 转向速率上限)`；无相邻动作样本取0 |
| 安全表现 | 20% | `max(0, 1 − 安全干预帧数 / 任务帧数)`；发生碰撞或非法换线时取0 |
| 实时计算 | 10% | `min(1, 单步时间预算毫秒 / 推理P95毫秒)`；无推理计时为null |

质量是可用分项的加权平均；例如手动驾驶没有推理计时，不伪造实时性分项。综合分是课程内解释性评分，不是经外部标定的安全认证。转向平滑分会随路线难度变化，只应比较相同测试集。可以展开每次运行的分数查看分项值、权重和版本。

自然加速度限制、惯性响应、转向速率限制、正常终止停车是物理行为，不作为安全干预扣分。状态强制停车、动作失效、算法故障、手动控制信号失效计入安全干预。

## 指标与统计口径

所有分布提供 `mean`、`p95`、`max`；无样本为 `null`。`frames` 是保存的全部物理帧，`task_frames` 不含结束后的 `safety_braking` 帧，后者用于对应任务步数预算。

| JSON 指标 | 定义与单位 |
|---|---|
| success / acquisition_success | 整体成功 / 满足合法接入条件；无真值null |
| acquisition_time_s | 首次合法接入时间，s；未接入null |
| completion | 已合法接入并连续走过的有序弧长 / 路线总长 |
| tracking_lateral_error_m | 任务阶段接入后的有序局部投影距离，m；不含终止滑行 |
| acquisition_lateral_error_m | 接入前的投影距离，m |
| heading_error_rad | 跟踪阶段车体航向与路线切向的绝对角差，rad |
| illegal_switches | 持续确认的换线事件与位置；当前一次成立即结束任务 |
| collisions / collision_count | 新接触事件（物件索引、仿真时刻）与数量，包括停车过程 |
| collision_duration_s | 检测到物件接触的物理步时长之和，包括停车过程 |
| lost_count / lost_duration_s | 算法实际输出 LOST 的进入次数 / 对应任务帧时长；不推断掉帧中间状态 |
| recovery_rate | LOST 后再次报告 TRACK 的次数 / LOST 次数；从未丢失null |
| inference_ms | 主进程一次 step 请求到校验完成的墙钟耗时，含通信、解码、推理；不含初始化、渲染、评分、界面 |
| realtime_miss_rate | 有计时响应中，推理耗时超过场景dt预算的比例 |
| timeout_count / timeout_rate | 硬超时次数 /（有效step响应数+硬超时数）；初始化超时也记故障 |
| speed_mps | 实际物理积分车速，m/s，包括停车过程 |
| simulation_time_s | 正常任务最后一帧的仿真时间，排除任务结束后的强制制动 |
| completion_time_s | 仅成功运行的首次到达终点时间；停车碰撞后为null |
| steering_rate_rad_s | 相邻实际前轮转角的绝对差 / dt，rad/s，包括停车过程 |
| steering_total_variation_rad | 相邻实际前轮转角绝对差的总和，rad |
| acceleration_mps2 | 相邻实际速度标量的绝对差 / dt，m/s² |
| vector_acceleration_mps2 | 相邻世界坐标速度向量差的模 / dt，m/s²；包含转弯方向变化，仅有向量遥测时提供 |
| jerk_mps3 | 相邻实际速度的二阶差分绝对值 / dt²，m/s³ |
| action_saturation_frames | 目标速度或转向超出边界被限幅的帧数 |
| safety_intervention_frames | 状态停车、动作失效、人工信号过期、算法故障停车帧数 |
| failure_counts | timeout/crash/protocol/invalid_output/exception 次数 |
| truth_metrics_available | 是否存在仿真真值 |
| score | 版本、总分、质量、分项值/权重与公式 |

CSV 单帧导出额外提供实际 `velocity_x_mps`、`velocity_y_mps`、`yaw_rate_rad_s`、物理 `acceleration_mps2` 和 `collision_ids`，便于分析惯性与碰撞。未标注素材不会被虚构为零误差；当前也不提供分割 IoU，因为没有对应人工标注集。

## 配对汇总与可比性

同批算法必须使用同一种执行模式和完整相同案例集合。创建时保存完整场景快照，算法插件规格、代码/权重 SHA256，平台源码哈希和测试集标识。每个排队作业开始前复核文件；代码变化使批次失效，不能把不同实现的结果合并排名。新批次需要重新创建。

只有所有方法的所有案例执行完成、没有取消且批次未失效时才给出成功率和排名：先按成功率，再按平均分排序。算法初始化失败、崩溃、超时等仍占预登记分母，未获得指标的执行失败计0分，不能通过丢弃失败抬高结果。进行中显示观察到的均分与已完成数，但不给正式成功率或名次。

均值计算时每个案例等权。界面「误差P95」和「推理P95」是**逐回合P95的均值**，不是混合全部帧后再次求P95。误差仅对有跟踪数据的运行计算，完成时间仅对成功运行计算；务必与成功率、完整覆盖数、执行失败数一起阅读。提前失败后的少量低误差不代表更可靠。

运行记录页使用 `comparison_key` 判断单次结果是否一致：完整场景（含相机、全部车辆惯性参数、物件、渲染版本、种子）、任务提示、执行模式、任务时限、推理超时、压力设置、物理/评分版本都参与。算法身份和参数不进入测试条件键。旧记录没有该键或条件不同时，显示不可公平排名提示，仍可并排查看。不同批次应检查完整测试集 SHA256，而不是仅比较地图中文名。

推理耗时受 CPU、进程通信及其他系统负载影响。该平台的串行批次减少同批并发干扰，但不保证主机上其他交互实验或程序没有负载；跨机器的实时性结果需记录环境后再解释。

## 后台接口

- `GET /api/benchmarks`：批次历史与方法汇总。
- `POST /api/benchmarks`：提交计划。字段 `name, algorithms:[{algorithm,execution,parameters}], families, map_ids, seeds, max_steps, timeout_s, stress`。
- `GET /api/benchmarks/{id}`：冻结计划、案例快照、逐项进度、指标、失败原因及汇总。
- `POST /api/benchmarks/{id}/cancel`：取消当前与剩余作业。
- `DELETE /api/benchmarks/{id}`：删除已结束批次汇总，保留单次记录。
- `GET /api/benchmarks/{id}/export?format=json|csv`：导出批次。

持久化目录为 `artifacts/benchmarks/{id}.json`，单次真实 Worker 结果仍在 `artifacts/runs/{run_id}`，保存独立 `benchmark_id`、案例/方法编号和测试集标识。命令行 `python run.py benchmark ...` 仍可用于脚本评测；前端历史管理的是通过批次接口创建的后台任务。

原有算法测试报告使用旧渲染/运动模型；新物件与惯性模型必须重新评测，不能沿用旧成功率。实现与历史评测见 [algorithms.md](algorithms.md) 和 [algorithm-results.md](algorithm-results.md)。不得观察保留测试结果后修改阈值、删除失败或继续将调参种子称为未知测试。
