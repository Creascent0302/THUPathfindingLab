# 评分、教师评测与公平比较

评分器版本 `1.0`。阈值集中定义在 `pathlab/evaluation.py`，在每次运行清单和批量计划中保存。不能在观察结果后修改阈值、删除失败实例或把已调参的种子继续称为未知测试。

## 有效进度与结束条件

私有目标路径是有序折线，累计弧长定义前进方向。评分器保存历史进度，投影仅搜索当前位置附近允许到达的弧长范围：可后退查询 0.35 m，向前查询本步实际位移的 1.5 倍加 0.025 m 数值裕度。不会在整条回头弯中直接取最近点作为进度。

默认合法接入区域为起点后 **0–0.5 m 弧长**。只有投影距离 ≤0.20 m 且航向误差 ≤0.45 rad 才算接入。接入前后的误差分别汇总，初始离线不会污染正常跟踪误差。

接入后，距离 ≤0.24 m、航向误差 ≤0.65 rad 时可增加连续进度。靠近终点但缺少前面的连续进度不会成功。达到目标末端前 0.18 m 以内，且当前仍符合跟踪约束，才判 `success`。

| 结束原因 | 规则 |
|---|---|
| success | 已合法接入，保持连续路径进度，当前处在终点容差内 |
| episode_timeout | 达到预先配置的步数限制；停车也消耗步数 |
| deviation | 接入后连续 2 s 不满足跟踪约束 |
| illegal_switch | 接入后，干扰线距车辆 <0.14 m、且比目标线近至少 0.035 m，持续 0.5 s |
| invalid_motion | 一步位移超过车速上限 × dt × 1.05 + 0.001 m |
| policy_finished | 算法主动 FINISHED，但评分器没有确认成功 |
| algorithm_* | 初始化、推理、进程、协议或输出失败 |
| user_cancelled / client_disconnected | 人工停止 / 浏览器租约过期 |
| source_complete | 素材处理完毕；不等于闭环驾驶成功 |
| recording_quota | 结构化记录达到限额 |

非法换线记录位置、仿真时间、当前目标进度。一次成立即结束回合，因此当前评分规则的换线次数最多 1。单帧离散抖动不会触发换线。姿态朝向与轨迹身份是评分依据，算法自己报告的 TRACK 或 FINISHED 不会覆盖它。

场景曲率超限、歧义或不满足核心接入条件，必须事先标为 stress。**当前不实现通用可达性求解或自动给压力场景判定 infeasible**；它们的预期不确定性由场景 notes 明示，算法可以减速、LOST/AMBIGUOUS 或停车。核心场景合法性检查与算法成功率无关。

## 指标字典

统计只使用实际已生成的记录；不提供的数据是 JSON `null` / CSV 空单元格 / 界面「不提供」。自动制动帧没有新推理，不产生伪造的视觉状态或目标误差。

| JSON 指标 | 定义、单位、适用条件 |
|---|---|
| success | 单回合布尔值；批量整体成功率为成功回合数 / 预先登记的全部回合数（含失败） |
| acquisition_success | 是否满足合法接入条件；批量初始化/接入成功率按全部回合计算 |
| acquisition_time_s | 首次接入的仿真时间，s；未接入为 null |
| completion | 当前连续有效目标弧长 / 目标总长；合法接入区域内的初始弧长按任务规则计入 |
| tracking_lateral_error_m | 接入后至结束的局部有序投影距离，均值、P95、最大值，m |
| acquisition_lateral_error_m | 接入前相同投影规则下的距离，均值、P95、最大值，m |
| heading_error_rad | 跟踪阶段车体航向与当前有序线段切向的绝对角差，均值、P95、最大值，rad |
| illegal_switches | 经过持续性确认的换线事件数组及位置；无真值为 null |
| lost_count | 算法进入 LOST 的次数；不把缺失输出/丢帧冒充 LOST |
| lost_duration_s | 收到 LOST 的推理帧对应 dt 之和；压力掉帧期间未观察到的状态不推断 |
| recovery_rate | LOST 后再次报告 TRACK 的次数 / LOST 次数；从未丢失时 null |
| inference_ms | 主进程一次 step 请求到响应校验完成的墙钟耗时，包含 IPC、插件解码与推理，均值/P95/最大值；不含初始化、渲染、评分和界面 |
| timeout_count / timeout_rate | 硬超时次数；次数 /（收到有效 step 响应数 + 超时数）；初始化超时也计为故障，详细方法写在失败消息 |
| speed_mps | 实际积分车速的均值/P95/最大值，m/s；感知素材无车速真值则 null |
| simulation_time_s | 包括安全制动的已推进物理时间，s；无仿真时 null |
| completion_time_s | 仅成功回合的完成时间，s |
| action_saturation_frames | 请求转角或速度发生边界限幅的帧数；速率限制独立记录在每帧事件中 |
| steering_total_variation_rad | 相邻实际转角绝对变化之和，rad；是控制抖动的基础量，不是稳定性综合评分 |
| safety_intervention_frames | 状态停车、动作过期、人工控制过期或算法故障停车涉及的帧数 |
| failure_counts | timeout / crash / protocol / invalid_output / exception 的次数 |
| truth_metrics_available | 是否有仿真真值；未标注视频永远 false |

初始化异常在推理开始前发生，可能没有帧；依然保存 manifest、失败类型和原始错误。不能仅从帧数判断运行是否有效。

当前没有带人工中心线标注的感知测试集，因此不报告分割 IoU 或中心线检测精度，也不会把车体横向误差当成视觉检测误差。`perception` 模式的闭环停车结果不宜与驾驶算法合并比较。

## 批量流程

```bash
python run.py benchmark --algorithms stop constant --seeds 101 102 --steps 400
```

命令先写 `artifacts/benchmark/plan.json`，再串行运行每个「算法 × 场景族 × 种子」组合。每个回合独立进程、独立 reset，参数相同，无界面、固定步长。最终生成：

- `report.json`：环境、计划、墙钟耗时、每次运行的全部指标及 run_id。
- `report.csv`：逐回合核心结果，可在表格软件中查看。
- `report.md`：各算法 × 场景族的样本量、成功数、平均进度与失败原因。

快速集采用 101、102；更大的预登记集合可采用 1001–1005 等新种子，但一旦用于调参，须将其转为开发/验证集合，并选择新的测试种子。生成 JSON 的默认 split 是 development；benchmark 创建的场景声明 test，使用者负责维护真实的数据使用历史。

同组比较应固定场景完整 JSON、相机/车辆参数、种子、公开提示、观测权限、输出执行方式、超时和压力设置、评分器版本。不同执行适配器或不同传感器权限必须分组。目前没有额外遥测模式，避免混用。

浏览器的对比表用于比较单次记录，不将一个最好回合伪装成平均结果；条件不同的记录必须看导出的配置后分组。阈值、失败样本、数据量和结束原因都应与结果一并提交。

## 实际探针结果与后续算法

本次真实运行了 2 个探针 × 8 类场景 × 2 个种子，共 32 回合；详见 `artifacts/benchmark/report.md` 和 JSON。

停车探针不会接入或完成任务；固定动作探针遇到初始航向偏差、弯道或邻近干扰时会偏离，甚至被判非法换线。这些失败用于检验平台能诚实报告问题，不能用来推断未实现的参考算法性能。

平台验收后的模块化算法目标仍是独立可行测试集 ≥95% 成功率、零非法换线；端到端算法需另行交付数据生成、训练、验证与真实 checkpoint。当前两项均未开始，不存在模型回退或随机权重冒充可用策略。
