# 实验框架架构

平台将学生算法与仿真、评测分离。默认注册表为空，界面只提供手动驾驶；ZIP 上传只进行结构与语法校验，实验启动后才由独立进程导入学生代码。

```text
网页 → HTTP / WebSocket → API → RunManager / Run
                               ├─ Renderer → Observation
                               ├─ WorkerClient → 学生进程 → AlgorithmOutput
                               ├─ 动作 / 局部路径执行器 → Vehicle
                               ├─ Evaluator（评测真值）
                               └─ RunStore → JSONL / 图像 / 报告
```

## 模块与边界

`pathlab/` 保持单层包。`sdk.py` 只定义公开模型、图像转换与接口，不导入仿真或评测；`config.py` 定义平台配置；`registry.py` 读取各数据目录自己的提交清单，并集中处理源码版与发行版路径。

`worker.py` 管理独立算法进程、JSON Lines 协议、消息大小和超时，结束时回收进程。源码版调用 Python 模块，发行版用同一可执行程序的内部 Worker 入口。插件的工作目录为自己的代码目录，辅助模块、相对资源文件均从该目录读取。此进程隔离用于生命周期和故障管理，不是恶意代码沙箱。

`engine.py` 负责逐帧任务循环；`simulation.py`、`dynamics.py` 和 `scene_objects.py` 负责相机渲染、惯性动力学及物件。`scenarios.py` 和 `map_editor.py` 负责场景生成、编辑与几何合法性。`adapters.py` 保留统一局部路径执行器，只消费学生输出路径和公开车体限制，不读取地图，不识别目标，不规划绕障。

`evaluation.py` 按从起点到终点的有序参考路径评测，区分获取目标、跟踪、合法绕障、错路和终止制动。评分不会因为算法自报 TRACK 或 FINISHED 就判定成功。`benchmark.py` 冻结场景、参数和实现摘要，串行运行学生提交的不同方法；失败保留，未完成的配对不排名。

`storage.py` 持久化完整场景、运行配置、每帧输出、指标及环境版本。默认写入源码根目录或可执行程序旁的 `artifacts/`；`--data-dir` 可覆盖。运行记录配额与提交配额分别计算，删除实验释放对应记录和图像，不删除地图或代码。

## 输入模式与坐标

仿真输入是车辆当前姿态的透视图，动作影响后续图像。单张图像只执行一次 step；图像序列或视频保持同一算法实例按序执行，动作不反作用于已录制素材，没有真值时不伪造闭环得分。回放读取已保存结果，跳转不再次调用算法。

车辆坐标原点在后轴中心，x 向前、y 向左；米、秒、弧度为基本单位。正转角向左，负目标速度请求倒车，零速请求制动。速度、车身朝向、速度向量与转角均受响应及变化率约束；正反向切换先制动。旧运动与渲染模型仅为历史地图和回放兼容保留。

## 本地服务与发行

前后端由一个服务提供，默认监听 127.0.0.1，`serve --lan` 监听所有网卡用于可信内网。一个实例是共享工作台，没有账号或远端存储同步。

发行包将除公开 SDK 和包标记外的后端模块编译为原生扩展，运行时资源放入 `_internal/`，用户数据在其外部。打包仅按白名单复制资源，不包含工作区数据、测试代码或 Git。构建与保护边界见 [发行说明](distribution.md)。
