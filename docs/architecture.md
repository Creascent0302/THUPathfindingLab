# 平台架构与边界

平台与参考算法均已实现。`algorithms/modular/` 封装共享视觉层和两种控制器，`algorithms/learning/` 将离线训练与部署推理分开，`algorithms/scanline.py` 提供简单图像基线；`algorithms/examples.py` 保留原有链路探针。所有部署插件遵守同一公开输入边界，具体结构见 [算法说明](algorithms.md)。

## 依赖方向

```text
前端 → HTTP / WebSocket → API → RunManager / Run
                                 ├─ 场景 → Renderer → Observation
                                 ├─ WorkerClient → 独立插件进程 → AlgorithmOutput
                                 ├─ PurePursuit / Action → Vehicle.advance(dt)
                                 ├─ Evaluator（私有真值）
                                 └─ RunStore → JSONL / 图片 / 报告
```

`dynamics.py` 提供无场景依赖的公开动作积分器，车辆仿真与算法内部预测共用。算法只能基于自身历史指令建立预测状态，不能获得实际速度向量。`sdk.py` 仅依赖 NumPy、OpenCV、Pydantic；不导入后端、场景或评分器。插件只实现 SDK 生命周期。`adapters.py` 不读取场景，Pure Pursuit 只消费算法局部路径、公开轴距和速度上限。

各职责集中在单层 `pathlab/` 包中，避免为每一个概念再创建目录。HTTP、任务循环、存储、传输、评分和仿真分别封装。注册表合并本地 JSON allowlist 与已校验的 ZIP 提交清单；服务器不导入插件类，只有独立进程加载它。删除任何一项注册不会影响其他算法和手动模式。

## 三种模式

| 模式 | 输入 | 跨帧状态 | 动作改变下一帧 | 真值评分 |
|---|---|---|---|---|
| 单帧 | 上传图像 | 初始化、重置、一次 step | 否 | 无标注时不提供 |
| 序列 | 视频解码/自然排序图像 | 同一独立实例依次 step | 否 | 无标注时不提供 |
| 仿真 | 当前车体姿态的透视渲染 | 同一独立实例 | 是 | 连续有序路径评分 |

序列素材按文件名中的数字自然排序，例如 `frame2.png` 在 `frame10.png` 之前。图像序列默认 20 FPS，HTTP 上传字段 `fps` 可指定；视频读取编码帧率。当前不支持可变帧率视频的逐帧 PTS，需预先转为固定帧率。素材自动按比例缩至 1280×720 以内，初始化坐标以缩放后的图像为准。

回放直接读已保存的结果，跳转不会调用 `step()`。想从某帧重新实验，须创建新的素材和新运行，不允许把未来时序状态直接带回过去。

## 坐标、相机和物理假设

- 世界为平面 XY，Z 向上，长度 m。目标数组从起点到终点有序。
- 车体原点为后轴中心，X 向前，Y 向左，正 yaw 逆时针；摄像头偏移相对于后轴中心。
- 等效前轮正转角左转。速度非负，不倒车。默认参数见 `config.py` 并完整写入每次运行的场景 JSON。
- 新场景使用 `inertial_v2`：先限幅目标动作、限制转角变化率，再以速度响应时间计算目标加速度并限制加加速度。零速指令持续施加制动直到速度过零时停稳，不产生倒车。
- 自行车关系 `v × tan(转角) / 轴距` 给出期望车身角速度；车身转向与实际速度向量分别经过响应环节。速度向量转动受横向加速度限制，位置由新旧速度向量的梯形积分更新。静止车辆不会原地改变朝向。
- 公开参数包含速度/车身转向/速度方向响应时间、最大加加速度与横向加速度。场景和运行记录保存这些参数及 `motion_model`；原始指令与实际状态分开存储。旧 `kinematic_v1` 保留原来的圆弧积分供历史兼容。
- 相机为无畸变针孔模型，使用地面平面反投影映射到世界栅格，再采样图像；传给算法的是 RGB 摄像头视图。
- 标定中的地面单应矩阵将**车辆坐标系的地面点**投到像素，不包含世界位姿。
- 绿色圆环和箭头绘制在地面；橙色终点环可见。RGB、线宽、标记尺寸、背景、照明、阴影、噪声、模糊和压力遮挡均可配置。
- 噪声由场景种子和帧号决定。初始姿态改变只能通过新建实验；运行中不能用 API 瞬移车辆。

几何合法性检查验证有限数值、点距、核心路径曲率、目标和干扰线距离、起点/方向箭头的投影可见性，以及保守的初始接入范围。生成器以 1.05–1.4 m 为基础半径构造弯道，多段可见场景逐渐增大回头弯半径，超过默认最小转弯半径约 0.56 m。此检查不运行被测算法，也不是通用障碍物环境中的完整可达性证明。

核心初始姿态限制在起点后方的保守接入区域；更大的航向偏差、无标记歧义、超限尖弯等用 `category=stress` 单独评测。核心场景没有路口与真实分叉。场景 v3 使用具有米制尺寸的交通锥、纸箱、隔离栏和圆桶。物件影响实际 RGB 投影、遮挡与阴影，启用碰撞的物件参与车辆足迹检测；碰撞会结束回合并请求制动。碰撞检测服务于评测，不是刚体接触力、变形或反弹仿真。

## 时间、故障和任务状态

生命周期：`queued → running → completed / failed / cancelled`。暂停是 `running` 上独立的 `paused` 字段。队列不无限等待：最多三个活动实验，超额请求立即明确拒绝。

默认仿真步长 0.05 s。推理慢时只增加墙钟耗时，不扩大物理步长；`realtime=true` 仅限制仿真不快于实时。WebSocket 刷新频率和绘图耗时不决定车辆位移。初始化/重置单次硬限时至少 5 s；推理默认 1 s、可配置 0.05–10 s。

确定性评测始终等待当前帧结果再推进。推理异常、进程退出、非法结果或硬超时结束当前回合，清理 worker 并按物理约束制动；不会调用替代算法。硬超时和非法响应原文最多保存前 32 KiB。

压力模式在固定仿真帧上注入延迟和随机掉帧。丢掉的观测不传给算法，下一次 `frame_id/timestamp_s` 可能跳跃；`dt_s` 仍是物理基准步长，算法可由时间戳求有效间隔。延迟动作按 FIFO 到达，超出 0.4 s（可配置）有效期后请求零速。延迟按**生成时刻**计算年龄，不能让很旧的动作到达后被当作新动作。

暂停允许已在计算的一帧完成。取消会终止 worker；取消、故障、成功、达到步数上限等终止路径均继续以固定步长制动至停稳，追加标记为 `safety_braking` 的实际轨迹。正常终止停车不算算法违规，停车中的碰撞仍会使成功变为失败。暂停冻结仿真时钟，是调试操作，不代表物理制动。这里没有硬件执行器。

Python 进程使用同一 JSONL 协议；stdout 仅传协议，Python 插件普通 `print` 转入有界 stderr 日志。Linux 终止整个进程组；Windows 使用 `taskkill /T`，未实测。服务退出清理活动任务。重启检查已保存运行的 owner PID，已退出进程的未完成记录标为失败；仍在同机命令行评测的进程不会被覆盖。

本地 PID 存活检测不是跨主机任务恢复协议。不要让多个机器/多个服务实例共享同一 artifacts 目录。

## 有界资源和数据留存

| 资源 | 限制 / 行为 |
|---|---|
| 实时并发 | 3 个运行 |
| 回合长度 | 最多 6000 推理步，另有有限的制动帧 |
| 协议消息 | 最多 8 MiB，一行 UTF-8 JSON |
| 单帧有效输出 | 最多 64 KiB |
| 算法参数 | 最多 16 KiB |
| 单次素材上传 | 合计 32 MiB、最多 600 帧 |
| 解码素材 | 每份最多 128 MiB |
| 算法 ZIP | 上传 32 MiB、解压 128 MiB、单文件 32 MiB、512 条目、100 份 |
| 自定义地图 | 目标路线最多 60 个控制点；最多 20 条干扰线、80 个物件、100 份保存地图；每条采样线最多 5000 点，全部线路合计最多 12000 点 |
| 原图大小 | 解码后检查最多 2400 万像素；规范化至 1280×720 |
| 逐帧结构记录 | 到 64 MiB 结束回合，最后一帧可能略超阈值 |
| 附加图像记录 | 每回合最多 128 MiB，超限记录事件并保留可重建数据 |
| 磁盘准入 | 200 次运行、50 份素材；新运行前检查 `artifacts/runs` 小于 2 GiB；算法包在 `artifacts/submissions` 单独限制 2 GiB，导入时计入解压大小。训练数据、评测报告和地图不占用运行配额 |
| WebSocket | 浏览器拉取下一条快照后再请求，最多一个在途快照 |
| 图表历史 | 最近 240 帧；完整历史仍在 JSONL 中 |
| 日志 | 服务运行日志 100 项、worker stderr 20 个有界块 |
| 内存运行实例 | 保留少量已结束任务，其余从磁盘回放 |
| 浏览器断线 | 30 s 无心跳取消任务；CLI 有最大步数、无需浏览器心跳 |

磁盘配额是准入限制，已经在运行的少量任务可在结束前超出全局阈值。不会静默删除已有结果。材料解码使用 OpenCV，不是恶意媒体安全隔离服务；仅导入可信课程素材。

平台侧真值与公开输入的边界通过集成测试检查，但同用户权限的恶意插件仍可能读取本地文件。ZIP 提交沿用这一权限模型；该入口面向教师本机受控使用，没有认证、账号级隔离、CPU / 内存容器配额或网络隔离，不能直接用于不可信的多人托管评测，也不声称能保护秘密地图。

## 编辑与提交模块

`map_editor.py` 分别构建目标路线、独立干扰线与三维物件。目标控制点的相邻方向夹角 θ 对应切线裁剪长度 `r × tan(|θ| / 2)`，直线与圆弧相切，按不超过 0.04 m 的间距采样。圆角半径不得低于车辆最小转弯半径的 1.02 倍；同一线段上的两个圆角不能重叠。生成后复用场景合法性检查，再检查非相邻目标路线的保守车宽间距。新建或修改目标路线时，初始姿态由第一段切线后退 1.5 m 生成；只修改干扰线、物件或外观不会重置原始姿态和目标采样。不会自动移动控制点来隐藏冲突；不保证高速动态可达，也不提供障碍物规划。

`Scene.design.waypoints` 和 `radius_m` 保存目标设计；`Scene.design.distractors` 保存每条干扰线的控制点与 `interpolation=polyline|smooth`。折线独立采样，圆滑模式使用保留首尾点的三轮角点裁切，再按不超过 0.12 m 的间距采样。干扰线没有驾驶曲率约束，也不会自动连接目标线；核心场景仍限制目标与干扰线的间距。实际运行读取完整的 `target_path`、`distractors` 和 `objects`，不依赖编辑器或原始文件。

`POST /api/maps/build` 接受设计及可选 `source_scene`，返回校验通过的完整场景、首帧、标定与几何摘要。`source_scene` 用于继承已有车辆、相机、外观、提示与未修改的几何；不会写入最终场景。旧设计中 `design.distractors=null` 表示保留源场景干扰线，显式 `[]` 表示清空。前端把没有编辑元数据的旧干扰线作为原坐标折线展示，不静默截断控制点或重新平滑。`GET/POST /api/maps` 读取与另存地图，`DELETE /api/maps/{id}` 删除地图；文件位于 `artifacts/maps/`。

编辑器中的「目标路线 / 干扰线 / 障碍物」模式分别控制画布点按行为，物件属性与干扰线属性在相应模式下显示。导入先由后端规范化及校验，避免旧 JSON 缺少新字段时误用新默认参数。编辑输出使用 `Scene.render_version=3`，旧地图会显示升级提示；这使三维物件及阴影进入实际 RGB，版本 2 为程序地面纹理，版本 1 为早期地面。旧运行记录仍按原版本重建；旧 v1/v2 场景未声明运动模型时继续使用 `kinematic_v1`，渲染升级不自动改变运动模型。前端立体视图为 SVG 正交投影，直接使用米制路线与车辆状态，不新增 WebGL / 仿真依赖。

`submissions.py` 使用受限的 ZIP 逐文件解压，完成语法和入口检查后原子登记到 `artifacts/submissions/`。每次上传有独立目录；重启重新读取清单。`WorkerClient` 复用现有 JSONL 执行链路，并设置代码工作目录与 SDK 搜索路径。

`DELETE /api/results/{id}` 仅允许删除已结束且记录写入线程已退出的任务；同步移除磁盘目录与内存索引。共享素材与算法包不删除。前端提供逐条 / 批量确认，部分失败时也刷新已成功删除的状态，并清除指向这些记录的回放。

## 网页批量评测

`benchmark.py` 管理有界、持久化的后台批次，复用同一个 `RunManager` 和独立 worker 生命周期。创建时冻结地图、种子、算法参数与实现摘要；每个方法执行相同案例。前端断开不会取消已明确创建的后台批次，用户可在评测中心取消；服务重启将未完成项目标为中断，不能继续给出完整排名。执行失败保留为零分，取消或不完整配对不排名。评分版本、完整车辆参数、渲染版本、提示与执行模式均用于比较检查。具体指标、限额与接口见 [评测说明](evaluation.md)。
