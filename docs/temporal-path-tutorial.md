# 从摄像头图像到局部路径：时序引导线识别教程

本教程以当前**不带避障的「时序拓扑」方法**为参考，教你逐步实现“找到原来的引导线，并输出它接下来的走向”。先读懂每一步，再尝试替换参考代码中的对应函数即可，不必一次写完整套算法。

「时序拓扑 + Pure Pursuit」和「时序拓扑 + MPC」使用相同的识别模块。本文讲它们共同的识别过程，最后改为输出 `local_path_m`，交给平台执行。接口基础见 [学生算法开发指南](student-guide.md)。

## 1. 先明确：我们要找的是哪条线

假设地面上有两条平行黑线，起点标记指向左边那条。车辆偏向右边后，右线可能离车更近。如果每帧都选最近的黑线，算法就会悄悄换线。

因此，识别任务分为三个问题：

1. **找候选**：图像里哪些地方像引导线？
2. **认身份**：哪一个候选是上一帧跟踪的原线？
3. **排顺序**：沿这条线往前走，会依次经过哪些点？

最后输出的是一串有顺序的车体坐标点，例如：

```python
local_path_m = [(0.5, 0.02), (0.8, 0.06), (1.1, 0.15)]
```

坐标原点在后轴中心，x 向前、y 向左，单位为米。上面的路径表示前方路线逐渐向左弯。它不是图像像素，也不是全局地图坐标。

整个方法的处理顺序如下：

```text
当前图像 → 鸟瞰图 → 暗线掩膜 → 骨架候选
                                     ↓
起点提示 / 上帧路径的运动预测 → 选择原线 → 沿骨架排序 → 局部路径
```

对应代码集中在 [vision.py](../algorithms/modular/vision.py)：`BirdEye` 处理图像，`TargetTracker` 保持身份，`trace_component` 生成有序路径。

## 2. 第一步：把透视图变成鸟瞰图

前摄像头中，远处的线更细，两条平行线也会逐渐靠近。在原图中固定使用“相距 10 像素”判断是否同一条线，远近含义不同。我们先把图像转换到地面坐标，让距离可以用米表示。

平台提供 `observation.calibration.ground_to_image`，记为 H。地面点与图像像素满足：

```text
[a, b, c]ᵀ = H · [x, y, 1]ᵀ
u = a / c，v = b / c
```

其中 `(x,y)` 是地面点，`(u,v)` 是图像像素。反过来，用 H 的逆矩阵即可把地面上的图像点转换成米制坐标。代码中的 `transform_points()` 就是这个计算。

生成鸟瞰图时，更方便的做法是：先铺一张地面网格，再计算每个网格点对应原图的哪个像素，使用 `cv2.remap()` 取颜色。当前 `BirdEye` 使用前方 0～6 m、左右各 3 m、间隔 0.025 m 的网格，共 241×241 个点。

网格的列、行记为 `(col,row)`，则：

```python
x = 6.0 - row * 0.025
y = 3.0 - col * 0.025
```

这样鸟瞰图上方表示远处，左侧表示车辆左侧。原相机看不到的网格点要标记为无效，不能把补白区域当成真实观测。

**这一转换只对地面成立。** 障碍物顶部、立柱等物体不能直接按同一矩阵当作地面线。本教程的方法没有障碍物识别和绕行能力。

动手检查：在鸟瞰图中画出候选点，再用 `BirdEye.pixels()` 投回原图。投回的位置应落在原先的引导线上；如果镜像或错位，先检查坐标和矩阵，不要急着调控制器。

## 3. 第二步：提取暗线，再压缩成骨架

### 3.1 为什么不能只用一个灰度阈值

黑线较暗，但阴影、物件边缘也可能较暗。当前 `BirdEye.extract()` 综合了三种线索：

- **亮度低**：像素比地面整体亮度低。
- **局部对比明显**：像素比周围背景更暗，符合细暗线的外观。
- **颜色接近中性**：RGB 最大通道与最小通道之差小于 50，减少彩色物件干扰。

先对灰度图做 15×15 的形态学闭运算，得到局部背景 `background`，再计算：

```python
contrast = background.astype(float) - gray
```

细黑线可能被背景估计填亮，因此原像素与背景差较大；大面积均匀暗区的内部差值则较小。当前实现还用有效区域灰度的第 70 百分位数调整亮度阈值，并要求对比度超过 `max(10, background * 0.18)`。

这里的闭运算用于**估计背景**。不要对最终道路掩膜做大范围闭运算来填缝，否则两条邻近但不连通的线可能被粘在一起。

起点彩色标记需要单独处理：按 `task_hint.marker_rgb` 在 HSV 中找相近颜色，把标记区域及一圈边缘从暗线掩膜中排除。否则箭头和圆环的暗边可能变成假的道路分叉。

### 3.2 为什么还要细化

二值掩膜中的路线有一定宽度，直接沿边缘走会抖动。`thinning()` 使用两阶段迭代细化，逐步删除边缘像素，保留接近单像素宽的中心骨架。

删除时不仅检查周围有几个邻居，还检查绕一圈时从背景到前景的变化次数，并交替使用两组方向条件，以减少删断线或破坏连接的情况。实现最多迭代 24 轮，不是任意图像上都保证完全细化。

随后按 8 邻域提取连通域，丢弃少于 12 个骨架像素的小碎片。每个候选保存两份坐标：

```text
pixels：鸟瞰网格坐标，用来判断像素是否相邻。
metric：同一批点的车体米制坐标，用来算距离和方向。
```

**连通域此时还是无序点集。** `np.where()` 返回的行列顺序不是车辆沿路线行驶的顺序，不能直接作为局部路径输出。

动手检查：先把每个连通域画成不同颜色。两条断开的邻线应保持两个候选；细化不应该替你把它们连起来。

## 4. 第三步：用起点提示确定原目标

第一次观察时没有历史路径，要借助 `task_hint` 建立身份。

对于彩色标记，当前代码对标记地面点做主方向分析：将点减去均值，再用 SVD 找延伸最明显的方向。由于主轴有正反两个方向，`principal_direction()` 选择与参考方向点积为正的一端，初始参考方向为车辆前方。

接着取标记点的中位数中心，沿主轴找到投影的第 97 百分位位置，再向前移 0.06 m，作为**锚点**。锚点是“预计路线从这里接出去”的位置，后续用它寻找候选。

这是一种适配当前标记和起步朝向的几何启发式，并不是完整的箭头语义识别。任意旋转、形状变化的标记不一定能正确初始化。

对于点提示，将首帧 `point_px` 反投影到地面；对于区域提示，取框中心再反投影。没有可辨识提示且出现多个候选时，返回 `AMBIGUOUS`；标记提示尚不可用时，可能保持 `UNINITIALIZED`。

初始化成功后，后续帧主要使用历史路径。首帧点击位置和框不会随车移动，不能一直拿固定像素重新选线。

动手检查：让车离干扰线更近，但起点标记仍指向目标线。算法应跟随提示指向的线，而不是距离车辆最近的线。

## 5. 第四步：预测旧路线，再和当前候选匹配

### 5.1 先把旧路径搬到当前车辆坐标系

车辆向前移动 0.1 m 后，原先在前方 2 m 的地面点应变成前方 1.9 m。若车辆同时转弯，旧路径还要旋转。未经变换就比较两帧路径，会把正常运动误判成路线变化。

设车辆相对上一帧的平移为 `t`、转角为 `yaw`，R 为对应旋转矩阵。对列向量有 `p_new = Rᵀ(p_old - t)`。代码使用一行一个点，等价写法是：

```python
path_now = (path_previous - translation) @ rotation
```

`TargetTracker.advance()` 同时变换路径、起点和终点记忆，并裁去最近路径点之前的大部分旧前缀，保留少量重叠点。

问题是：平台没有提供实际里程计。当前 [MotionEstimate](../algorithms/modular/control.py) 根据上次请求动作、时间差和公开车辆参数估计运动。它包含转角变化率、加减速和惯性响应，不能简单认为“发出速度 v 后，车辆立刻以 v 行驶”。

这是预测，不是真实位姿。动作延迟、掉帧后的指令过期制动都会使预测偏离实际，需要下一帧图像不断校正。

### 5.2 用一小段路径匹配，而不只比较一个点

在预测路径中，当前代码选取 `x > 0.65 m` 且距车小于 2.5 m 的点，从中生成锚点、少量支持点及参考切向。

对于每个候选：

1. 找到离锚点最近的位置。
2. 取该位置周围 0.23 m 内的点，估计候选局部切向。
3. 计算各个历史支持点到候选的最近距离，取中位数。
4. 加上方向不一致的代价。

对应公式：

```text
score = median(历史支持点到当前候选的最近距离)
        + 0.08 × (1 - 候选切向 · 参考切向)
```

两个切向都应归一化。没有历史支持点时，距离项改用锚点到候选的最近距离。

距离项回答“它还在原线预计出现的位置附近吗”，方向项回答“它的局部走向是否接近”。多点中位数比单点距离更不容易被局部噪声影响，但仍可能在近邻同向线路上产生歧义。

### 5.3 最小代价不等于身份确定

`TargetTracker.observe()` 同时检查两个条件：

- 最佳代价是否足够小：正常跟踪默认门限 0.16；标记初始化放宽到 0.42，其他未初始化情况为 0.5。
- 最佳与次佳是否分得开：代价差小于 0.035 时，返回 `AMBIGUOUS`。

例如，两个候选代价为 0.02 和 0.25，可以接受第一个；若为 0.02 和 0.045，虽然第一个更小，但优势太小，应停车保留身份。

这些是当前实现的经验参数，代价含有按米尺度加权的方向项，不应把 0.16 理解成严格的道路横向误差上限。

动手检查：在邻近路线场景中记录各候选代价。先查预测、分割和提示是否正确，再调整门限；直接放宽门限可能让车辆更容易换线。

## 6. 第五步：沿骨架连接关系生成有序路径

选中连通域后，仍不能按 x 坐标排序。回头弯可能先向前再向后，同一个 x 也可能对应两个不同位置。

`trace_component()` 把骨架视作一张小图：每个骨架像素是节点，相邻像素之间有边。追踪过程为：

1. 从关联到的锚点附近节点出发，按参考切向选择下一步。
2. 只考虑相邻、且尚未访问的节点，不允许跳到空间上接近的另一条断开线。
3. 有多个选择时，比较位移方向与当前切向的夹角，并向后看最多 6 层，偏向还能继续延伸的分支。
4. 用最近几步的位移更新切向，逐步跟随弯曲的路线。
5. 沿正向、反向各追踪一次，将反向结果倒序后与正向结果拼接。

当前分支优先级相当于 `方向余弦 + 0.25 × 可继续延伸深度`；方向过于反向时停止。若一个拐角已有正交连接，会抑制多余的对角连接，减少像素小环导致的错误走向。

最后沿**已经排好顺序的路径**做 5 点局部平均，再每隔一个点采样。不要把相邻道路的点一起平均，否则平滑后的线可能落在两条道路之间。

这说明两种约束的分工：**时序关联负责选择原线，骨架连接负责确定原线怎样延伸。** 它不是完整的路网拓扑推理；真实交叉连接、分割粘连，以及同一连通域中的复杂分支仍可能选错。

生成路径后，当前实现要求至少 4 个点，首尾距离至少 0.15 m；否则认为结构不足，返回 `LOST`。输出点必须保持路线行驶顺序，不能排序成点云，也不要擅自补出看不到的长路线。

## 7. 第六步：短时看不见时如何处理

当前无避障版在关联门限不通过时，可以短暂使用经过运动变换的旧路径：默认记忆时间为 0.45 s，置信度随缺失时间降低：

```python
confidence = 0.65 * math.exp(-missing_s / memory_s)
```

超过记忆时间后返回 `LOST`，不把另一条线当成新目标重新启动。若两个候选代价接近，则直接返回 `AMBIGUOUS`；若提取出的路径结构不足，也会返回 `LOST`，不是所有失败都会进入预测续行。

当前代码还识别橙色终点：只有终点色块中心靠近已选路径末端时才记住它。该终点距车小于 1.2 m、进入近端盲区且关联失败时，有一段小于 3 s 的特殊预测过渡。它服务于驶入已看到的终点，不能作为普通长时间丢线的处理方法，是否完成仍由平台判定。

教学实现可以先完成“丢线就停车”，再加短时记忆，最后阅读终点处理。每加一层，都确认它仍然在保持原线身份。

## 8. 把识别结果作为局部路径提交

### 8.1 最小输出

上传时选择「局部路径」，`step()` 返回：

```python
return AlgorithmOutput(
    status="TRACK",
    confidence=0.9,
    local_path_m=path.tolist(),
    centerline_px=camera.pixels(path).tolist(),
)
```

`path` 是 N×2 数组，单位米；`centerline_px` 只是投回原图的调试叠加线。SDK 要求路径有 2～4096 个点，平台执行器还要求每点距后轴不超过 30 m。找不到可靠路径时，返回 `LOST` 或 `AMBIGUOUS`，并省略路径。

平台默认执行器会从有序路径中选取前视点，通过 Pure Pursuit 计算转角，再按曲率和置信度调速。因此这里不需要返回 `action`。

### 8.2 时序预测必须与实际使用的执行器一致

原来的 `VisualDriver` 自己生成动作，可以直接用上次动作预测运动。改为路径输出后，动作由平台生成；如果仍用原算法控制器生成一份不同的动作来更新历史路径，预测就会不一致。

下面的接线示例在算法内部调用**与平台相同的路径执行器**，只为估计下一帧运动。返回值仍然只有路径，没有动作。这是对当前平台执行规则的推算，不是读取执行回执；延迟和掉帧压力测试下仍可能产生误差。

这个示例可在**当前完整平台**中保存为 `algorithm.py` 并上传，模式选「局部路径」。它复用现有 `TargetTracker`，用于先跑通流程；随后按前面的步骤实现自己的 `vision.py`，把对应导入改为 `from vision import TargetTracker`，并一起打包。`algorithms.modular` 和 `pathlab.adapters` 是本仓库模块，不属于任意环境都自带的公共 SDK。

```python
from algorithms.modular.control import MotionEstimate
from algorithms.modular.vision import TargetTracker
from pathlab.adapters import PurePursuit, execution_action
from pathlab.sdk import Action, AlgorithmOutput


class StudentAlgorithm:
    def initialize(self, config, public_context):
        self.limits = public_context.get("vehicle_limits")
        if self.limits is None or public_context.get("execution") != "path":
            raise ValueError("请在仿真中选择局部路径模式")

    def reset(self, initial_observation, task_hint):
        self.tracker = TargetTracker()
        self.motion = MotionEstimate(self.limits)
        self.adapter = PurePursuit(
            self.limits["wheelbase_m"], self.limits["max_speed_mps"]
        )
        self.last_action = Action(steering_angle_rad=0, speed_mps=0)
        self.last_time = initial_observation.timestamp_s

    def step(self, observation):
        elapsed = observation.timestamp_s - self.last_time
        if elapsed < 0:
            return AlgorithmOutput(status="ERROR", diagnostics=["时间倒退，请重置"])
        if elapsed > 0:
            translation, yaw = self.motion.advance(
                self.last_action, elapsed, observation.dt_s
            )
            self.tracker.advance(translation, yaw)
        self.last_time = observation.timestamp_s

        track = self.tracker.observe(observation, max(elapsed, observation.dt_s))
        confidence = track.confidence
        if track.predicted:
            # 默认路径执行器速度不超过 min(max_speed, 0.8) * confidence。
            # 降低置信度，使纯预测期间的请求速度不超过 0.35 m/s。
            base_speed = min(self.limits["max_speed_mps"], 0.8)
            confidence = min(confidence, 0.35 / max(base_speed, 1e-6))
        path = track.path
        output = AlgorithmOutput(
            status=track.status,
            confidence=confidence,
            local_path_m=path.tolist() if path is not None else None,
            centerline_px=self.tracker.camera.pixels(path).tolist()
            if path is not None else None,
            candidates_px=track.candidates,
            debug={"prediction_only": track.predicted},
            diagnostics=[track.reason],
        )
        self.last_action, _ = execution_action(output, "path", self.adapter)
        return output

    def close(self):
        pass
```

这个示例沿用了当前视觉识别模块，但路径模式使用的是平台默认控制器，不是原来的调速 PP 或 MPC，因此不能直接沿用原算法的闭环成绩。置信度也是经验控制系数，不是“跟对道路的统计概率”。

## 9. 按这个顺序完成自己的实现

| 阶段 | 要完成的内容 | 检查方式 |
|---|---|---|
| 单帧候选 | 鸟瞰、分割、骨架、连通域 | 原图叠加是否贴在线上；断开的线是否仍分开 |
| 初始身份 | 提示解析、锚点、候选选择 | 干扰线更近时，仍选择提示指向的线 |
| 有序路径 | 沿骨架追踪与轻度平滑 | 回头弯不跨接；点的顺序沿路线推进 |
| 时序关联 | 运动预测、支持点匹配、歧义判断 | 平行干扰场景不因最近距离变化而换线 |
| 缺失处理 | 停车，再加入有限时间预测 | 短时遮挡能恢复，长时间缺失会停车 |
| 路径执行 | 输出 `local_path_m`，匹配平台执行器 | 先低难度闭环，再测试 S 弯和同线多段可见 |

看回放时，先判断“识别出的路径是否正确”，再判断“车辆是否跟得上”。路径错误应先查分割、身份和连接；路径正确但车摆动，应再查控制和运动预测。占道障碍物需要另行设计避障，本教程输出的仍是原引导线，不能把它当成绕行路线。
