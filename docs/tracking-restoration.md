# 完整本地平台恢复与无障碍寻迹验收

本次恢复以线上功能引入前的 `4033504` 为功能对照，保留之后的本地惯性制动、倒车和存储修复，移除线上网关、容器部署及浏览器目录同步。完整平台仍有手动驾驶、算法 ZIP 提交、内置方法、地图三层编辑、地图重名处理、主页加载、图片/视频分析、批量评分、结果对比、回放、导出和删除。此前学生分支和学生发行包没有被覆盖；当前完整版本应在仓库目录运行 `python run.py`。

## 修复的实际问题

1. 最近的 `c12a3ec4df374e98a9e8c15d1e5bbfbb` 实验带着工作台残留的点提示运行，首帧关联失败，随后一直停车并以 `acquisition_failed` 结束。新仿真忽略旧提示：后轴中心直接位于路线首点，朝向首段（即箭头）方向，初始速度为零。预览、地图编辑、实际 Worker、批量和命令行采用同一个 `Scene.at_start()`。
2. 原固定前向初始化锚点无法处理起点即急弯。现在使用已知起步位置/方向和公开最小转弯半径，检查可见候选能否通过短直线与圆弧接续，拒绝没有合理接续的远处回返线。
3. 时序关联曾硬编码只使用 `x > 0.65 m` 的历史路径。紧弯中的正确线段可能全部在此范围以内，造成识别后立即丢线。现在通过公开相机标定，把历史路径投影到当前图像，选取实际视野内的支持点。
4. 从起点直接出发后，原相机可能看不到紧贴起点的弯道。新地图默认俯角 0.65 rad、水平视场角 95°；已保存地图的相机参数保留。无法观察起点之后 1.5 m 内一小段路线的配置会明确报错，提示调整相机，不以远处可见线冒充起步目标。
5. 分支切换后，忽略的 `frontend/dist` 可能仍是另一版网页，造成界面与 API 不匹配。`run.py` 启动服务前检查网页源文件更新时间，需要时自动重新构建。旧学生版草稿中的提示字段被迁移清除，地图、物件和干扰线保留。

算法仍只使用 RGB、相机标定、先前请求动作和公开车体参数。首帧知道自己在路线起点，但不获得世界坐标、地图、目标点序列或未来图像。正常跟踪距离、航向、进度窗口和非法换线门限保持原值；由于起步规则改变，评测和评分版本均改为 6.0，避免与旧结果混合排名。
