# 在线课堂：固定网址、学生本地保存、临时隔离运行

## 给教师：你现在还需要什么

代码已增加 `python run.py online` 启动方式。原来的 `python run.py` 仍用于本机实验，不能把它直接开放成多人公共服务。

目前这台 Ubuntu 机器显示内网地址 `172.16.2.4`，没有检测到 Docker。这个地址通常需要实验室网络或 VPN 才能访问，是否存在公网映射要由管理员确认。代码修改不会自动申请域名、证书或开放学校防火墙，也尚未将当前机器发布到互联网。

可以把下面这段话发给实验室管理员：

> 我们要部署寻迹课程实验平台。需要一个学生可访问的固定 HTTPS 地址，优先使用学校分配的域名；请确认校内 / 校外访问范围，并配置 DNS、TLS 证书和反向代理。服务器需要 Docker，学生代码在没有外网、没有主机目录挂载的独立容器中运行。部署文件在仓库 deploy/，步骤见 docs/online-deployment.md。不要直接把原来的本机 8000 端口开放到公网。

不要求学生安装完整平台。桌面 Chrome / Edge 可授权一个文件夹自动保存；不支持目录授权的浏览器可使用 ZIP 导入与手动下载。

## 学生如何使用

1. 打开教师提供的 HTTPS 网址，输入自己的访问码。
2. 点击“选择本地目录”，选择一个专用于本课程的文件夹；网页只能访问明确授权的目录，不能凭输入 `D:\实验` 这样的字符串直接读取磁盘。
3. 已有工作区时，从该目录恢复地图、算法包、素材、运行记录和批量结果；新目录从空工作区开始。
4. 正常使用地图编辑、算法提交、运行和回放功能。实验和批量任务全部结束后，页面每 10 秒检查一次变化并自动保存；也可以点击“立即保存到本地”。
5. 离开前停止实验及批量任务，等待保存成功，再点击“结束会话”。仍在运行、保存失败、权限被收回时，页面会提示，不会假装已保存。
6. 再次打开网址，登录并重新授权上次的目录，即可恢复。不能从备份继续执行原 Python 进程；已经完成的记录可直接回放。

目录中有 `pathlab-workspace.json` 索引和两个交替写入的 `workspace-a.zip` / `workspace-b.zip`。先完整写新压缩包，再提交索引，网络中断或写盘失败时保留上次成功版本。不要单独删除索引指向的压缩包；迁移时复制整个目录。每个压缩包最多约 130 MiB，本地需为两个版本留足空间。

为了避免相互覆盖，同一浏览器、同一网站一次只允许一个标签页打开工作区。正在运行时刷新页面，可重新授权目录后进入仍存活的临时会话，不会强制用旧备份覆盖新数据。

手动下载模式需要学生自己确认下载完成，不能自动写入文件夹；ZIP 包含已提交的数据，未提交的编辑器草稿仅在原浏览器中缓存。目录模式还会保存工作台设置与地图草稿。浏览器清理权限后需要重新授权，清理浏览器缓存不等于删除已经写入普通本地目录的文件。

## 设计与限制

```text
学生浏览器 ── HTTPS ── Nginx ── 在线网关（登录、席位、时限）
    │                              │ Docker exec 字节流
    │                       每名学生独立临时容器
    │                       仿真 / Python 算法 / 临时文件
    │                              │
    └── 授权本地目录 ←── 工作区快照 ─┘
```

本地记录和学生运行环境中的输出可被修改，不能作为防篡改的正式成绩。正式评分需要教师在受控评测环境中重新运行提交代码。

服务端运行仍然需要临时内存和文件空间，无法只靠“存到学生电脑”解决资源攻击。本方案把**长期保存**移到学生电脑，把**计算期消耗**设为有上限：

| 项目 | 当前限制 |
|---|---|
| 访问 | 每名学生独立随机访问码；不提供公开注册 |
| 同时在线席位 | 默认 4，可配置；满员返回 429 |
| 每个会话 | 1 CPU、1 GiB 内存（包括 tmpfs）、禁用额外交换空间、128 个进程 |
| 工作区容量 | 可保存的数据最多 128 MiB；地图、算法、素材导入合计最多 48 MiB |
| 临时文件硬限制 | artifacts 的 tmpfs 384 MiB，/tmp 的 tmpfs 192 MiB，均计入容器内存上限 |
| 运行并发 | 每学生 1 次实验；批量测试串行调度 |
| 开始新运行 | 已用临时数据达到 60 MiB 时拒绝，给新记录和制动帧留空间 |
| 图像记录 | 线上不重复录制相机 PNG；仿真回放由场景与保存位姿重建，上传素材仍保存原帧 |
| HTTP | 请求体最多 130 MiB；每会话最多 4 个在途请求，并限制请求频率 |
| WebSocket | 每会话最多 2 个；仅接受快照拉取，检查来源和会话所有权 |
| 回收 | 无浏览器心跳约 5 分钟后回收；单会话最长 4 小时，即使仍有活动也会结束 |
| 退出 / 重启 | 清除本实例的临时容器；不会清理本机模式的 artifacts |

容器使用只读根文件系统、非 root 用户、默认 seccomp、移除全部 Linux capabilities、禁止提权；不挂载宿主目录、Docker socket、教师凭据，不发布网络端口，并使用 `--network none`。网关通过 `docker exec` 的有界输入输出管道访问容器内的回环 HTTP 服务，学生算法无需获得网络访问权限。

这些限制降低一名学生耗尽整台机器资源的风险，不代表无限人数可以同时使用，也不代表 Docker 等同于独立虚拟机。运行不可信代码应使用专用教学服务器，及时更新宿主内核、Docker 和依赖。不要与实验室的重要数据或其他关键服务混合部署；开放给未知公众时应再使用更强隔离、账户管理和边缘流量防护。

容器入口还设置独立的 4 小时进程时限，即使网关意外退出，也不会无限运行。

网关本身不保存实验文件。临时容器中的数据仍会在计算期间上传到服务器，因此这不是“数据从不离开学生电脑”的方案。正在执行的实验尚未形成最终快照；突然断电、关闭浏览器、服务器重启或达到硬时限时，**只能恢复最后一次成功保存的版本**。浏览器关闭事件不能保证最后一次上传 / 下载完成，不能依赖它实现自动兜底。

单个文件夹是一个当前工作区，不会无限累积所有历史。数据接近上限时，先保存并复制整个目录作归档，再在当前工作区删除旧运行，或结束会话后选择新的空目录。备份恢复只允许写入空的临时工作区，避免覆盖已有实验。非法路径、符号链接、重复路径、过量文件和超限解压内容会被拒绝。

## 管理员部署步骤

以下为准备好的配置，必须在管理员确认的专用服务器上执行。`lab.example.edu`、路径、用户名和证书文件都是占位值。

### 1. 安装基础环境并构建

准备现代 Docker Engine、Nginx 和项目所需的 Python 环境。确认 Docker 的 cgroup 内存、进程和 CPU 限制可用；建议至少 8 GiB 内存用于默认 4 个并发席位，并为网关、操作系统及镜像留出空间。

在项目目录执行：

```bash
python scripts/setup.py --mirror
# 项目自带 Node 在 .venv 中，setup.py 会构建教师服务器上的静态网页。
docker build -f deploy/Dockerfile -t pathlab-session:latest .
```

镜像构建需要联网下载依赖；运行时学生容器禁网。默认镜像与基础平台一样，不安装可选 PyTorch，CNN 算法会显示不可用；如课程需要额外库，由教师在镜像中统一安装并重新评估内存预算。不能依赖学生代码在运行时 pip 安装包。

Dockerfile 只复制运行所需代码，不复制 artifacts 或部署凭据；`.dockerignore` 排除本机数据和虚拟环境。

### 2. 创建个人访问码

```bash
.venv/bin/python scripts/create_access_codes.py --count 40 --output access-codes.json
```

文件中每个 `student001`、`student002` 对应一个随机访问码。分别发放，不要把整份文件或一个共用访问码发给全班。生成脚本不会打印访问码，也不会覆盖已有文件。将此文件放到 `/etc/pathlab/access-codes.json`，权限限制为部署用户可读。

### 3. 设置网关参数

参考 [online.env.example](../deploy/online.env.example)，配置 `/etc/pathlab/online.env`：

```text
PATHLAB_PUBLIC_ORIGIN=https://实际分配的域名
PATHLAB_ACCESS_CODES_FILE=/etc/pathlab/access-codes.json
PATHLAB_SESSION_IMAGE=pathlab-session:latest
PATHLAB_MAX_SESSIONS=4
PATHLAB_INSTANCE=course
```

来源地址必须与学生浏览器地址完全一致，不带尾斜线。`PATHLAB_INSTANCE` 用来标记该课程的容器，一个实例只运行一个网关进程，不要增加 Uvicorn workers。网关重启时会回收同实例遗留容器；不同课程需要不同实例名、端口和访问码文件。

首次调试可在设置好上述环境变量后运行：

```bash
.venv/bin/python run.py online --port 8000
```

网关只监听 `127.0.0.1`。正式服务使用 [pathlab-online.service](../deploy/pathlab-online.service)，修改部署用户、项目绝对路径和环境文件位置后交给 systemd 管理。部署用户需有 Docker 权限；这属于管理员权限边界，不应使用普通学生账户运行网关。

### 4. 配置固定 HTTPS 入口

让学校管理员将分配的域名解析到正确的入口机器，配置可信 TLS 证书，再参考 [nginx.conf](../deploy/nginx.conf) 接入网关。配置包含 HTTPS、请求大小限制、连接数和频率限制，并关闭代理请求 / 响应落盘缓冲。

只有 Nginx 的 HTTPS 入口对学生开放。内网课程可以使用学校可信证书与 VPN / 校园网入口；校外访问还需网络管理员允许相应路由或映射。不要把不受信任的自签证书报错当作部署完成。

如果要为所有人提供共同的课程地图，可把地图 JSON 发给学生导入。各会话的地图库是独立的，不会直接读取教师本机 artifacts/maps，也不会看到别人的实验。

### 5. 上线前验收

- 用两个不同访问码登录，确认彼此看不到、不能删除对方的地图和结果。
- 授权目录，上传一个模板算法，完成短实验；确认目录出现索引和 ZIP。
- 保存并结束会话，再登录恢复；确认地图、算法、回放及评分仍可读取。
- 测试拒绝目录授权、网络中断、满员和会话回收提示。
- 在专用测试会话中验证 Docker 的内存、CPU、进程、禁网、无主机挂载限制；通过 `docker inspect` 检查实际生效的配置。
- 根据机器负载和一节课的并发人数调整席位；不要只提高并发而不检查总内存。限流配置还需结合学校出口共用 IP 的情况调整。

本次开发环境未提供 Docker，已通过 API 和浏览器层验证的部分不能替代真实服务器上的容器运行及 HTTPS 验收。公网地址、TLS、学校网络连通性和真实隔离压力测试仍需部署时完成。
